# قواعد ومعايير المعمارية والكود النظيف الموحد (Strict Architecture & Clean Code Rules)

يتم تطبيق هذه القواعد بشكل دائم ومستمر على كامل مسارات العمل دون أي استثناء:

## 1. منع استدعاء `$request->validated()` نهائياً:
- لا يُستخدم `$request->validated()` أو `$request->validated('field')` في أي متحكم أو خدمة أو مستودع أو مهمة.
- الاعتماد الكلي على ملفات الـ `FormRequest` والوصول المباشر للحقول المحققة كخصائص للكائن `$request->field`.
- تمرير كائن الطلب المكتمل النوع (Typed Request) مباشرة إلى دوال الـ Service.

## 2. نمط المتحكم النحيف الصارم (Strict Lean Controller):
- يقتصر دور الـ Controller حصراً على: استقبال الـ `FormRequest` المحقق -> تمريره إلى الـ `Service` -> إعادة النتيجة مغلفة بـ `ApiResponseTrait` وموارد الـ `Resource`.
- ممنوع منعاً باتاً فتح أو إغلاق `DB::transaction` في الكونترولر.
- ممنوع منعاً باتاً كتابة أي استعلام مباشر أو استدعاء للنماذج داخل الكونترولر.
- ممنوع كتابة أي منطق أعمال أو شروط معقدة في الكونترولر.

## 3. تنظيم الاستيرادات ومنع المسارات الكاملة (Clean `use` Imports):
- ممنوع كتابة مسارات الكلاسات مدمجة داخل الكود (مثل `\App\Models\User` أو `\Illuminate\Support\Facades\DB`).
- استخدام عبارات `use` صريحة في ترويسة كل ملف لكافة النماذج والخدمات والواجهات والاستثناءات والـ Enums.

## 4. طبقة الخدمة (Service Layer):
- هي المكان الوحيد المعتمد لإدارة معاملات قاعدة البيانات `DB::transaction`.
- التنسيق بين المستودعات (Repositories) ومعالجة الملفات عبر `FileUploadService`.
- إطلاق مهام الطوابير (`Queue Jobs`) الخاصة بالإشعارات والرسائل.
- لا تسجل `SystemLoggerService` يدوياً للعمليات التي تسجل تلقائياً عبر `BaseRepository`.

## 5. طبقة المستودعات (Repository Layer):
- المسؤولة الحصرية عن استعلامات وعمليات قاعدة البيانات عبر `BaseRepository`.
- توثيق وتسجيل حركات الإضافة والتعديل والحذف الفردي والمجمع تلقائياً في السجلات.
- مسميات العمليات المجمعة الموحدة: `bulkDelete`, `bulkRestore`, `bulkForceDelete`.
